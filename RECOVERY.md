# RECOVERY notes

This repository's tracked source is **recovered by decompiling the released APKs** after the original source tree was lost, plus the compiled APK artifacts.

> ⚠️ **This is recovered/decompiled source, not the original.** Comments, original variable/parameter names, and Gradle build scripts are gone. Class and method structure, resources, and `AndroidManifest.xml` are faithful. Treat it as a reconstruction baseline, not a drop-in original project.

## Native migration (v2.3.2)

Starting at v2.3.2 the app moved most logic into a native library
(`lib/arm64-v8a/libghostguard.so`) fronted by `com.ghostmapx.security.NativeGuard`.
**The C/C++ source for that `.so` cannot be recovered by decompilation** — only
the compiled binary survives (disassembly only). The Java layer in 2.3.2 shrank to
6 classes as a result. To fully restore 2.3.2 behaviour you must rewrite the native
portion from memory or reverse the `.so` at the assembly level.

## Buildable Gradle project (2026-10-06)

`gradle-project/` is a compilable Android Gradle restoration of `recovered-src`
(v2.2.0 build 17). Base is the **original release APK** `com.ghostmapx.app_2.2.0_17.apk`
— not the backend-wired rebuild, not the Appteka MOD repack.

- Build: JDK 17 + Android SDK (platform 35, build-tools 35.0.0) + Gradle 8.10,
  then `gradle :app:assembleDebug`. Full notes: `gradle-project/BUILD.md`.
- Dependencies: `app/libs/applibs.jar` = original APK's `classes.dex` via dex2jar
  with `com/ghostmapx/**` stripped (17 classes body-patched to restore members
  dex2jar dropped; pristine copy kept outside the repo); Xposed API 82 via Maven
  (`compileOnly`, provided at runtime by LSPosed).
- 19 source files fixed vs `recovered-src` (jadx decompile errors: SAM signatures,
  field types, constructor refs); `R.java` removed (regenerated by AGP);
  `p011f/` sources added (2 files).
- Verified 2026-10-06: package `com.ghostmapx.app`, versionCode 17 / versionName 2.2.0,
  all 25 top-level `com.ghostmapx` classes present in dex, `apksigner verify` passes.
  **Not device-tested** — hook behavior needs a rooted + LSPosed device.
- Backend is NOT wired in (`recovered-src` predates it) — port the backend
  integration separately.
